## 2. Caveats (know these before relying on it)

### Blocking

1. ~~**The working tree is uncommitted.**~~ ✅ Resolved: everything is committed as `8c45f61` and
   pushed to `origin/main`.

### Functional

2. ~~**Canvas deletion is not wired to the model.**~~ ✅ Fixed on `feat/drawing-depth-trust`:
   `onNodesDelete`/`onEdgesDelete` remove the element/relationship from the model via
   `removeElements`/`removeRelationships` (incl. view nodes/edges and artefact links), with
   regression tests in `packages/core/src/workspace-editing.test.ts`.
3. ~~**No autosave.**~~ ✅ Fixed on `feat/drawing-depth-trust`: debounced autosave (1.5 s) with a
   saved/unsaved badge; explicit Save still works.
4. ~~**No error boundary.**~~ ✅ Fixed on `feat/drawing-depth-trust`: per-tab `ErrorBoundary` with a
   recoverable panel (`apps/web/src/components/ErrorBoundary.tsx`).
5. **No version history UI.** The server stores snapshots, but there is no list/diff/restore.
6. **No conflict UI.** A `409` produces a toast, not a theirs-vs-yours review.
7. **`.archimate` is best-effort.** Elements, relationships, views, bounds, and properties survive;
   custom icons and styling do not.
8. **IaC mapping is heuristic.** Review proposals before applying. Re-import is idempotent by
   `iacAddress`, but there is no drift UI yet.
9. **OIDC is unit-tested, not live-tested.** RS256/JWKS verification works in tests; it has not been
   exercised against a real Entra/Keycloak instance.
10. **i18n is incomplete.** The app has EN/NB, but many new workspace/settings strings are
    hardcoded English.
11. **Bundle size.** 797 KB / 250 KB gzip in one chunk; analysis, AI, and import packages are not
    code-split.
12. **Server sample data can be stale.** The seed only runs when `data/models.json` is absent.
    Delete the file to reseed the richer sample (domains, artefacts, owner).
13. **CORS is open** (`origin: true`) and persistence writes synchronously on every request.
14. **Share links are gzip URL fragments** and refuse models too large for a URL; they are not a
    substitute for server sharing.
15. **No schema migration** for native JSON; older files are not upgraded.
16. **No performance testing** at 2,000+ elements; tables are not virtualised.
17. **No accessibility audit**; keyboard navigation is limited to undo/redo and native controls.
18. **No real-time collaboration.** Async server collaboration with optimistic locking only.
19. **`openarch check` default rules are noisy** — 36 warnings on the official ArchiSurance model;
    there is no baseline/waiver mechanism yet.
20. **Generated views are materialised snapshots.** The recipe is stored in native JSON and can be
    regenerated, but AOEF export carries the nodes/edges, not the recipe. Regenerate after model
    changes, or use the **Regenerate** button in the editor.
21. **The view designer is new.** It has unit tests but no E2E coverage; the preview is read-only.

### Environment

20. The AOEF conformance tests use `xmllint`; they skip if it is not installed. CI installs
    `libxml2-utils`.
21. Headless screenshots can show an empty workspace list because IndexedDB seeding is async; a
    real browser is fine.

## 3. Gaps for a useful modelling / drawing tool

The biggest gap is no longer features — it is **drawing depth**. The canvas is functional but
basic compared with a dedicated diagramming tool.

### A. Drawing and editing (highest impact)

| Gap | Consequence |
|---|---|
| Delete not synced to the model | Confusing, risks accidental loss or resurrection |
| No multi-select bulk actions | Cannot assign domains/environments to many elements at once |
| No copy/paste/duplicate | Repeating similar structures is slow |
| No align/distribute | Diagrams look unpolished |
| No snap-to-grid or alignment guides | Manual pixel alignment |
| No edge bendpoints or reconnection | Routing is automatic only (`smoothstep`) |
| No on-canvas label editing | Every rename goes through the inspector |
| No containers / nested nodes | Cannot express grouping visually |
| No z-order controls | Overlaps are hard to manage |
| No context menu or shortcuts | Power users are slowed down |
| No drag-and-drop from the palette | Add-element flow is a dropdown |
| No comments anchored to elements | Feedback is disconnected from the canvas |
| No presentation mode | Sharing a view means exporting an image |

### B. Trust

Autosave · version history + restore · conflict review · error boundary · validation on save ·
schema migration · backup/export-all · undo for metadata changes (currently covered by `commit`).

### C. Export and presentation

PDF export · print stylesheet · themes (light/dark, corporate) · better SVG fidelity ·
DOCX/PPTX packs · Confluence publish.

### D. Workflow

IaC drift detection · Git-native workspaces (open folder/repo, commit/push) · command palette ·
global search across workspaces · bulk edit · onboarding tour · sample gallery · dark mode.

### E. Enterprise

OIDC end-to-end + group→role mapping + member-management UI · governance UI (approval inbox,
baseline diff, immutable approved baselines, waivers) · value-stream view · C4/Structurizr bridge ·
ArchiMate 4.0 registry · Jira/Confluence/ServiceNow connectors · SCIM.

### F. Platform and community

Published Docker image · hosted demo · `npx openarch` · docs site · CONTRIBUTING · issue templates ·
release process · PWA/desktop wrapper.

## 6. What not to do next

- Do not add more enterprise connectors before the drawing experience is solid.
- Do not build a CMDB, ITSM, or a full TOGAF process engine.
- Do not add real-time CRDT editing.
- Do not chase Gartner-MQ feature parity.
- Do not launch a marketplace before adoption.
